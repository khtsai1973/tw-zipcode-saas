「正規化地址」做了哪些處理？
查詢前會先清洗地址，結果寫入「正規化地址」欄，方便對照原始輸入與實際用來查碼的字串。目前包含：
  • 去除空白、標點與括號；全形數字／符號轉半形
  • 台 → 臺（如台北市 → 臺北市）
  • 去掉開頭已填的郵遞區號（3／5／6 碼）
  • 縣市簡稱與舊名對應（北市、台北縣 → 新北市等）
  • 舊鄉鎮市改制（鳳山市 → 高雄市鳳山區、板橋市 → 新北市板橋區等）
  • 國字／大寫門牌轉阿拉伯數字（一五七號 → 157號、之三 → 之3、第十二樓 → 12樓）
  • 門牌格式統一（216-1 → 216之1號、12F → 12樓）
  • 路名別名（台灣大道 → 臺灣大道）
  • 安全剝離村里／鄰（不誤傷「仁里路」等路名）
  • 基隆／新竹／嘉義缺行政區時，依路名推論行政區

例：鳳山市光復路１５７號 → 高雄市鳳山區光復路157號

「查詢原因」如何區分？
不再只顯示「查詢失敗」，結果會標明原因，例如：
  • 地址格式錯誤
  • 缺少縣市
  • 缺少路段
  • 查無對應路段
  • 門牌無法判斷
  • 外部服務逾時
  • API錯誤
  • 使用本地Fallback成功（官方服務未命中，改以本地路段成功）
